# Q4 reconciliation (draft)

Pure replay, no IO, no changes to canonical records. Events are exact JSON objects with a content hash of the source, offset-aware observation time, explicit reign identity, extractor ID, full permanent progression (stars, relics, unlocked habit levels) and full seasonal stats. No unknown critical values admitted. Separate trusted approval registry maps exact event digest to reviewer ID; same-ID approval rejected. Hash is not a signature and reviewer identity is not authenticated by this module. Production admission/authentication, durable append-only log, concurrent writes and revocation/correction policy are still required.

Reign registry is explicit, never guessed. Historical seasonal observations remain indexed by reign; new reign starts empty until observations arrive. Sorting by observation time makes replay deterministic. Same source with differing approved payloads or same dragon/time with differing approved fields quarantines implicated events. Unapproved candidates cannot poison approved observations. Replay refuses lower stars/habits or same-reign lower levels/XP; relic balances may decrease. These are conservative game assumptions, not proof all legitimate game mechanics are monotonic; correction policy must be separately designed. Full habit slots required; unknown names are not inferred. Persistent identity metadata (class, trait, affinities, ability names) is not part of this first event schema; preserve legacy evidence, integrate reviewed catalog separately.

Rollback is read-only observation-time cutoff replay, not transaction-time audit or deletion. Duplicate event digests are idempotent. State fingerprint invalidates stale formation inputs when permanent/seasonal state or reign changes; commander/equipment/catalog dependencies still require independent fingerprints in Q5. No actual formation changes.

Migration stages all 38 existing dated profiles without inventing per-image hash, timestamp, reviewer approval or reign ID. Preserves both source documents by digest and their profile records; no events generated. Actual migration to a durable authoritative ledger is blocked on metadata verification and independent approval. No private screenshot uploads.

Test-first commit precedes production; fixture completeness corrections added on the implementation commit and independently exercised by mutation tests. CI adds behavioral tests and 12 targeted source mutants, in addition to previous gates. No multi-agent identities available; no independent review or release score. Q3 holdout and habit recognition remain blockers. Do not merge until evidence reviewed.
