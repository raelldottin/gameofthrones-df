# Q7 — Bounded supervisor contract (draft)

Research → Plan → Write → Review → Benchmark → QA/Eval → accept or repair. Each dispatched stage gets a unique agent ID and context ID; reuse anywhere in the run blocks. The dispatcher is injected. A request binds the input Git commit, frozen policy, prior artifact bytes/hash, candidate hash, benchmark manifest hash and repair feedback. The reply must echo the request digest and provide bytes matching its declared artifact digest. History retains bytes as hex and digests for audit. A repair invalidates downstream artifacts, routes to the earliest indicated stage, and uses new identities. Default policy is three repair cycles; upper bound ten. Provider exceptions block. No retries are silently swallowed.

Acceptance: exact declared gates (minimum tests, mutations, holdout, architecture), exact finite metrics, threshold AND non-regression, candidate/fixture/baseline binding, independent QA scores with evidence references and dimension caps (35/25/20/10/10); minimum 95, no high/critical issues. No fake default score. A pass with high issues blocks; repair requires explicit issue evidence. The implementation does not interpret free-text artifact claims or verify the semantic adequacy of evidence. The acceptance result is a contract status, not release authorization; even synthetic accepted runs set release_authorized=false.

## Integration boundary
The caller must supply an authenticated dispatcher that launches an actual new isolated worker session per request, enforces process timeout/resource budget, stores artifacts durably by hash, and independently verifies CI/benchmark reports against the frozen fixture, candidate Git tree and baseline. The Write artifact hash identifies bytes, not intrinsically a Git tree; external adapter must bind artifact to actual commit/tree. IDs returned by arbitrary untrusted callback are NOT identity proof. No provider credentials, shell subprocess or automatic merges. No live agent backend in this slice. In-memory synchronous run is not crash-recoverable; adapter must provide durable execution, trusted receipts, authorization and replay protection. Use Hermes Swarm Protocol or Boundroom as a future adapter only after inspecting their actual interfaces. No guessed API commands.

Tests use a deterministic simulated dispatcher and source mutations. Synthetic 100/100 result tests the gate, not product quality. Q3 holdout, Q4 authoritative ledger, Q5 tactical validation and Q6 predictive evidence remain blocked. No production score, no real agent execution, no canonical writes.
